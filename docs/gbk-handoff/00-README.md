用户已经选择直接改源码。不要重新提议虚拟盘、WSL 转换层、工程副本同步或只覆盖几个工具的扩展。

本包是实施交接，不是已完成产品。当前只有 Fork、开发分支、源码审计和文档；GBK 功能、二进制构建和 Release 均未完成。接手 AI 必须推进到真实产物，不能把写完文档视为完成。

## 4. 固定决策

- 首版以 Windows x64 为实际验收平台；其他平台保持构建兼容，未运行不得声称支持已验证。
- 分发命令拟定为 `ompg`，首版与 `omp` 并存，不直接覆盖用户原版安装。
- 默认未启用编码适配时保持上游行为；GBK 仅对明确选定的工程源码路径生效。
- 保留 `@oh-my-pi/*` 工作区内部导入名和现有工具协议；不向官方 npm 命名空间发布。
- 编码策略独立于模型输出；由 Core 决定，AI 不得通过工具参数临时忽略严格校验。
- 首版 GitHub 标签拟定 `v18.8.4-gbk.1`，创建前必须确认未被占用；编号以真实发布状态为准。
- 上游贡献是后续选项，不阻塞个人 Fork 的实现、测试和发布。

## 5. 每阶段都采用相同执行节奏

1. 检查前置条件和当前 diff。
2. 阅读列出的入口及关联测试，记录事实与假设。
3. 实现一个可以验证的行为闭环。
4. 运行阶段测试，保存命令、退出码、SHA、实际结果。
5. 更新台账，列出通过、不通过、未验证和恢复方式。
6. 前置条件满足后继续下一阶段，不在每一小步反复要求用户确认。

阶段编号用于依赖管理，不代表工作量相等。P03/P04、P07/P08、P10/P11 和 P14/P16 是高风险阶段，必须分别验收。

## 6. 完成标准

以下全部完成，才能声称首版交付：

- 支持范围内的 GBK/UTF-8 真实字节测试通过，Hashline 陈旧编辑保护仍有效。
- 默认 UTF-8 行为、插件基本加载、子 Agent、配置隔离及原生模块隔离通过。
- 所有未覆盖的外部写入路径有明确限制与错误，不能静默损坏文件。
- 用本 Fork 对应源码构建 Rust addon 和 Windows 程序，干净环境可启动和编辑。
- GitHub Release 标签、源码 SHA、二进制 SHA-256 一致，下载后的资产再次验证通过。
- 安装、升级、卸载、回滚均不破坏原版 OMP。

E630 实际编译验收单独列项。若用户未提供可用工程和编译命令，可以交付明确标注限制的通用 GBK 预发布版；不能声称“E630 已验收”，也不能发布正式稳定版。
